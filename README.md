# SkillSwap API

Отдельный Django REST Framework бэкенд для React-приложения SkillSwap.
Стандартная модель Django `User` хранит email в полях `username` и `email`;
остальные данные пользователя находятся в связанной записи `Profile`.
Навыки, избранное, заявки и уведомления хранятся в SQLite.
Изображения хранятся в `media/`; в базе сохраняются относительные пути к ним.

## Локальный запуск

Нужен Python 3.12. В корне проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

`migrate` создаёт таблицы и заполняет справочники городов, категорий и
подкатегорий.
Проверка сервера: `GET http://127.0.0.1:8000/health/`.

Для админки: `python manage.py createsuperuser`, затем `/admin/`.
На запрос `Username` введите email и повторите его в поле `Email`.
Новых обычных пользователей создавайте через API регистрации.

## Моковые пользователи

Исходные данные, которые нужно коммитить в репозиторий бэкенда:

- `mock_data/Моковые пользователи.xlsx` — таблица;
- `mock_data/user_41/avatar.png` — аватар пользователя `user_41`;
- `mock_data/user_41/skill_01.png`, `skill_02.png` и т. д. — его фотографии навыка.

Для следующего пользователя добавьте заполненную строку в таблицу и папку с тем
же `mock_id`, например `mock_data/user_42/`. Допустимы JPG, PNG и WebP до 5 МБ
за файл. В папке должен быть ровно один файл `avatar` с допустимым расширением;
все остальные изображения считаются фотографиями навыка и упорядочиваются по
имени файла. Строки шаблона, где заполнен только `mock_id`, пропускаются.
В колонке `gender` пустая ячейка и «Не указан» дают `null` в API.

`Profile.mock_id` — уникальный постоянный ключ мокового пользователя. Обычные
пользователи имеют `mock_id = null`. Импорт ищет существующего пользователя по
этому ключу, поэтому его числовой `User.id` при обновлении не меняется.
Заполненные строки добавляются или обновляются; моковые пользователи, которых
больше нет среди заполненных строк, удаляются. Если заполненных строк не осталось,
удаляются все моковые пользователи; обычные пользователи остаются. Перед
изменением базы команда проверяет структуру таблицы и все указанные изображения.
Ошибка останавливает синхронизацию без удаления пользователей.

Общий пароль задаётся переменной окружения `SKILLSWAP_MOCK_PASSWORD` (от 8
символов). Email для входа строится из ключа: `user_41@skillswap.invalid`.
Пароль не хранится в репозитории. Запустить синхронизацию вручную:

```bash
export SKILLSWAP_MOCK_PASSWORD='ВАШ_ОБЩИЙ_ПАРОЛЬ'
python manage.py sync_mock_users
```

При каждом локальном `python manage.py runserver` синхронизация выполняется
автоматически. Для этого создайте рядом с `manage.py` файл `.env` по образцу
`.env.example` и задайте в нём `SKILLSWAP_MOCK_PASSWORD`; `.env` исключён из
Git. Для PythonAnywhere скопируйте `deploy/pythonanywhere_wsgi.py` в WSGI-файл
из вкладки Web и создайте `.env` в каталоге проекта на сервере, например:

```dotenv
DJANGO_DEBUG=0
DJANGO_SECRET_KEY=ваш_случайный_секретный_ключ
DJANGO_ALLOWED_HOSTS=beluza.pythonanywhere.com
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
SKILLSWAP_MOCK_PASSWORD=ваш_общий_пароль_для_моков
```

После обновления репозитория выполните `pip install -r requirements.txt`,
`python manage.py migrate` и только затем нажмите Reload. При каждом запуске WSGI
синхронизация выполнится автоматически. Оставшиеся моковые пользователи сохраняют числовые
ID и действия в приложении (например, избранное); поля профиля, навык, пароль
и фотографии берутся из таблицы и папок заново.

Исходные файлы хранятся в `mock_data/`. Рабочие копии изображений Django
складывает в `media/`, которая исключена из Git. Не редактируйте `media/`
вместо исходных файлов: изменения будут заменены при следующей синхронизации.

## Авторизация

API использует только DRF `TokenAuthentication`. После входа или регистрации
фронт получает `token` и добавляет к защищённым запросам заголовок:

```http
Authorization: Token <token>
```

Для API не используются cookie-сессии и CSRF-заголовок. Админка Django работает
со своей сессией. Встроенный DRF-токен один на пользователя: выход удаляет его,
после следующего входа выдаётся новый. Для проверки командой используйте
отдельные учётные записи. В продакшене используйте HTTPS.

## API

Все пути начинаются с `/api/` и заканчиваются `/`. JSON используется везде,
кроме запросов с файлами, где нужен `multipart/form-data`.

| Метод | Путь | Авторизация | Результат |
| --- | --- | --- | --- |
| POST | `auth/register/` | нет | Пользователь, его навык и токен |
| POST | `auth/login/` | нет | `{token, user}` |
| POST | `auth/logout/` | да | Удалить токен |
| GET, PATCH | `me/` | да | Свой профиль, включая `has_unread_notifications` |
| GET | `cities/` | нет | Список городов |
| GET | `categories/` | нет | Категории с подкатегориями |
| GET | `users/` | нет | Краткие данные всех карточек пользователей и поля для фильтрации |
| GET | `users/{user_id}/` | нет | Полные данные для детальной страницы пользователя |
| GET, POST, PATCH | `me/skill/` | да | Просмотреть, создать или изменить свой единственный навык |
| POST | `me/skill/images/` | да | Добавить фотографию навыка |
| DELETE | `me/skill/images/{id}/` | да | Удалить свою фотографию |
| GET | `favorites/` | да | Предложения избранных пользователей |
| PUT | `favorites/{user_id}/` | да | Установить `is_favorite: true/false` |
| POST | `exchange-requests/` | да | Предложить обмен пользователю |
| GET | `notifications/` | да | Все свои уведомления, новые первыми |
| POST | `notifications/read-all/` | да | Отметить все новые прочитанными |
| POST | `notifications/clear/` | да | Без тела; физически удалить только прочитанные |

### Цвета плашек навыков

Цвет фона определяется категорией навыка и передаётся в поле `color`
в формате `#RRGGBB`. `GET /api/categories/` возвращает цвет каждой категории,
а вложенные подкатегории — тот же цвет своей категории.

| Категория | `color` |
| --- | --- |
| Бизнес и карьера | `#E7F2F6` |
| Иностранные языки | `#EBE5C5` |
| Дом и уют | `#FAEBD7` |
| Творчество и искусство | `#F7E7F2` |
| Образование и развитие | `#EAEAF8` |
| Здоровье и лайфстайл | `#E9F7E7` |

В `GET /api/users/` и `GET /api/users/{user_id}/` для плашки «Может научить»
показывайте `skill_offer.title` с фоном `skill_offer.color`. Для плашек
«Хочет научиться» используйте `wanted_subcategories[].name` и
`wanted_subcategories[].color`. Цвет уже есть в ответе карточки;
отдельный запрос к справочнику или случайный выбор цвета не требуется.

Регистрация собирает три шага формы в **один заключительный запрос**:

```json
{
  "email": "anna@example.com",
  "password": "password123",
  "name": "Анна",
  "birth_date": "1998-04-21",
  "gender": "female",
  "city_id": 1,
  "about": "Люблю фотографию",
  "wanted_subcategory_ids": [1, 9],
  "teach_subcategory_id": 23,
  "skill_title": "Портретная фотография",
  "skill_description": "Научу снимать портреты"
}
```

Поле `gender` принимает два строковых значения или `null`:

| Значение API | Вариант в форме |
| --- | --- |
| `male` | Мужской |
| `female` | Женский |
| `null` | Не указан |

Если пользователь выбрал «Не указан», в JSON можно передать
`"gender": null` или совсем опустить поле. В `FormData` поле `gender`
просто не добавляйте: строка `"null"` не равна JSON `null`. В ответах
сервер вернёт `"gender": null`. При `PATCH /api/me/` передайте JSON `null`,
чтобы сбросить выбранный пол; если поле не передано, оно не изменится.

Для формы регистрации загрузите города через `GET /api/cities/`, а категории
и вложенные в них подкатегории — через `GET /api/categories/`.

### Выбор категории и подкатегории на фронте

Используйте ответ `GET /api/categories/` как единственный источник списка
подкатегорий в форме. У каждой подкатегории в этом ответе есть `category_id`.

1. Один раз загрузите категории с вложенными подкатегориями.
2. Пока категория не выбрана, показывайте все подкатегории.
3. При выборе категории показывайте только её подкатегории. Если ранее
   выбранная подкатегория относится к другой категории, сбросьте её.
4. При выборе подкатегории найдите её `category_id` и автоматически выберите
   соответствующую категорию.

В состоянии каждой пары полей храните `categoryId` для отображения и
`subcategoryId` для отправки. В запрос регистрации отправляйте только ID
подкатегории: для навыка «Хочу научиться» —
`wanted_subcategory_ids: [subcategoryId]`, для навыка «Могу научить» —
`teach_subcategory_id: subcategoryId`. ID категории отправлять не нужно:
сервер определит её по подкатегории.

При отправке файлов используйте
`FormData`: добавьте `avatar`, повторите поле `skill_images` для каждой
фотографии и `wanted_subcategory_ids` для каждого ID. Не задавайте
`Content-Type` вручную: браузер добавит границу multipart. Допустимы JPG,
PNG, WebP до 5 МБ за файл. Количество фотографий навыка не ограничено.

При загрузке файлов весь запрос передаётся как один `FormData`, включая
текстовые поля. JSON отправляется только когда файлов нет:

```js
const body = new FormData();
body.append('email', email);
body.append('password', password);
body.append('name', name);
body.append('birth_date', birthDate);
if (gender) body.append('gender', gender);
body.append('city_id', String(cityId));
body.append('about', about);
body.append('teach_subcategory_id', String(teachSubcategoryId));
body.append('skill_title', skillTitle);
body.append('skill_description', skillDescription);
for (const id of wantedSubcategoryIds) {
  body.append('wanted_subcategory_ids', String(id));
}
if (avatar) body.append('avatar', avatar);
for (const file of skillImages) body.append('skill_images', file);

await fetch(`${API_URL}/auth/register/`, { method: 'POST', body });
```

Для этого запроса не задавайте заголовок `Content-Type` вручную.

`GET /api/users/` возвращает для каждой карточки `id`, `name`, `age`,
`gender`, `city`, `city_id`, `about`, `avatar_url`, `date_joined`,
`wanted_subcategories`, `skill_offer`, `likes_count` и `is_liked`.
`date_joined` — дата регистрации пользователя из стандартной модели Django,
по ней фронт может выбрать карточки для раздела «Новое». Элементы
`wanted_subcategories` содержат `id` подкатегории, `name`, `category_id`
и `color`. Краткий `skill_offer` содержит `title`, `subcategory_id`,
`category_id` и `color`. Оба ID сразу доступны для фильтров по категории
и подкатегории в режимах «Хочу научиться» и «Могу научить»; `gender` и
`city_id` нужны для фильтров по полу и городу. Этот же формат карточки
используется в `GET /api/favorites/`.

`GET /api/users/{user_id}/` возвращает полные данные пользователя и навыка,
включая описание и фотографии, а также `likes_count`, `is_liked`
и `exchange_offered`. В ответах пользователей и навыка нет
`skill_offer.created_at`: дата для раздела «Новое» относится к регистрации
пользователя. Публичные ответы содержат возраст `age`, но не дату рождения
`birth_date`. Собственная дата рождения есть в `GET /api/me/`, где она нужна
для редактирования профиля. Авторизованный фронт должен передавать токен и в GET-запросах,
чтобы `is_liked` и `exchange_offered` отражали состояние текущего
пользователя. У гостя оба поля `false`.
Список пользователей, уведомлений, избранного и все справочники возвращаются
**целиком, без серверной пагинации**.

```json
{"target_user_id": 42}
```

Это тело `POST /api/exchange-requests/`. Запись об обмене связывает отправителя
и адресата. Первый запрос создаёт уведомление **отправителю** и возвращает 201.
Повторный возвращает 200 без новой заявки и без нового уведомления. Оба
ответа содержат `exchange_offered: true`. Открытие колокольчика через
`GET /api/notifications/` не помечает сообщения
прочитанными. Каждое уведомление об обмене содержит `target_user_id`:
кнопка «Перейти» открывает детальную страницу именно этого пользователя.
Если фронт сохраняет маршрут `/skill/:id`, параметром `:id` в нём служит
**ID пользователя**; данные страницы загружаются через `/api/users/{id}/`.
Красная точка исчезает после `read-all/`; `POST /api/notifications/clear/`
без тела удаляет только
прочитанные записи. `/api/me/` возвращает вычисленное поле
`has_unread_notifications`, отдельный запрос для точки не нужен.

Пример элемента `items` из `GET /api/notifications/`:

```json
{"id": 7, "type": "exchange_offered", "message": "Вы предложили обмен Ивану", "target_user_id": 42, "is_read": false}
```
